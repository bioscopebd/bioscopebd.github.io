# BioscopeBD cross-platform workspace

The original website files remain at this folder's top level. They were copied, not edited. Edit `00-shared-web/` for the app versions, then run `npm run sync` from this folder to update the **generated** web bundles in `pwa/`, `android/app/www/`, `ios/app/www/`, and `windows/www/`. Sync replaces those generated bundle files; it leaves native project settings alone.

## Requirements

- Node.js 22 or newer (Node 24 was available during preparation).
- Android: Android Studio 2025.2.1 or newer with its SDK and bundled JDK. The debug APK can be built without a signing key; the release AAB needs a private keystore.
- iOS: a Mac with Xcode 26 or newer. The workflow builds an unsigned simulator app. Device/App Store builds need Apple signing assets.
- Windows: Rust (MSVC target), Microsoft C++ Build Tools with Desktop development with C++, and WebView2. MSI building may need the Windows VBScript optional feature.

## PWA

Host the contents of `pwa/` at an HTTPS origin. `manifest.json` and `service-worker.js` make the core HTML/CSS/JS available offline after the first online visit. Remote sample images and Google Fonts are cached only after they have been loaded once; system fonts and image backgrounds remain usable offline.

For a local preview, run `npx serve pwa` or any static HTTP server and open the printed URL. A file opened directly with `file://` cannot install a service worker.

## Android: resume at home

The native Android project is already generated and synced. Android Studio, Android SDK 36, and a portable Java 21 are present. From PowerShell:

```powershell
cd "$env:USERPROFILE\Desktop\bioscopebd"
npm run sync
$env:JAVA_HOME="$env:USERPROFILE\Desktop\bioscopebd\android\tools\jdk-21.0.12.1+1"
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
cd android\app
npx cap sync android
cd android
.\gradlew.bat assembleDebug
```

If successful, copy `android/app/android/app/build/outputs/apk/debug/app-debug.apk` into `android/release/`. The debug APK has **not** been built or run yet. The release AAB and keystore are also pending. Release signing in `android/app/android/app/build.gradle` reads `BIOSCOPEBD_KEYSTORE_FILE` and `BIOSCOPEBD_KEYSTORE_PASSWORD` from the environment; create and back up a private keystore before publishing. The `android/keystore/` and release folders are gitignored.

On current Android versions, status-bar background color may be controlled by edge-to-edge system behavior. The app uses a dark web background and safe-area CSS.

## iOS

The iOS Xcode project and icon/splash assets have already been generated on Windows. On a Mac, from `ios/app`, run `npm ci` and `npx cap sync ios`. Open `ios/app/ios/App/App.xcodeproj` in Xcode, choose your Apple Developer team, and test on a simulator and a device. Build an archive and export an IPA from Xcode when signing is configured. This project uses Swift Package Manager, so there is no CocoaPods `.xcworkspace`.

If the whole `bioscopebd/` folder is a GitHub repository, manually run `.github/workflows/ios-simulator.yml` in GitHub Actions. It syncs the project on a macOS runner and uploads an **unsigned simulator app**. The workflow has not been run and does not publish to the App Store.

## Updates and publishing

1. Edit `00-shared-web/` only. Update the service-worker cache version when changing offline assets.
2. Run `npm run sync` from the root; it updates only the generated web bundles.
3. Re-sync/rebuild each native platform with its own commands above.
4. Deploy `pwa/` to HTTPS hosting. A domain name alone does not host the files.
